# Сторінки та версії

Оновлення інтерфейсу: «+ Додати версію» розміщено в лівому блоці «Версії». Імпорт відкривається окремою робочою областю, без таблиці перекладів під формою. Додавання мови доступне в «Мови проєкту». Під час створення сторінки або версії користувач задає назву (1–100 символів); `PageVersion.name` зберігає її, а `number` залишається внутрішнім порядковим номером. Для старих записів без назви показується «Версія N». Інформаційні плашки над перекладами прибрано; обмеження редагування історичних версій залишаються.

## Поведінка для користувача

У проєкті є сторінки (наприклад, «Акаунт» та «Main»). Це не Git-гілки. Кожна сторінка має свій список версій 1, 2, 3. Два списки показані окремо в лівій панелі. Натискання сторінки відкриває її останню версію; нижній список дозволяє переглядати попередні.

Власник створює сторінку разом із першим JSON. Для оновлення вибирає останню версію й натискає «Імпортувати нову версію». Форма показує зміни до запису в базу; «Скасувати» не створює нічого. Кожне підтвердження створює наступний номер, у тому числі для ідентичного файлу.

Редактор перекладає, рецензент перевіряє останню версію. Старі версії можна читати й експортувати, але не редагувати. Збереження перекладу створює дію в історії, а не версію сторінки. Всі учасники зберігають доступ до історичних знімків свого проєкту.

## Модель даних

`Project → LocalizationPage → PageVersion → TranslationKey → Translation`.

- `LocalizationPage`: назва, проєкт; назва унікальна в проєкті.
- `PageVersion`: номер у межах сторінки, дата, назва завантаженого файлу, статистика імпорту.
- Кожна версія має незалежні ключі й переклади. Однакові назви ключів допустимі в інших сторінках і версіях.
- `SourceText.version` — редакція конкретного тексту, не номер версії сторінки. Це зберігає сумісність із наявною історією.
- `Translation.copiedFromTranslationId` — ID перекладу, з якого зроблено копію. Старі дії не приписуються новому автору; їх можна прочитати в попередній версії. Поточні дії записуються в історію нового перекладу.

## Перенесення

Порівняння виконується за ключем із останньою версією тієї самої сторінки:

| Оригінал | Результат у новій версії |
|---|---|
| Не змінився | Копія перекладу, статусу, коментаря та причини доопрацювання |
| Змінився | Копія тексту перекладу, статус OUTDATED; старе зауваження не переноситься |
| Новий ключ | Порожній переклад, NEW |
| Ключ відсутній | Не копіюється; залишається в попередній версії |

Нова версія не позначає OUTDATED переклади старої версії. Enter дозволяє повторно подати навіть незмінений текст із OUTDATED, якщо перекладач перевірив його актуальність.

## Цілісність і доступ

Імпорт виконується транзакційно із Serializable. Спільне транзакційне блокування сторінки в імпорті та збереженні захищає стару версію від запізнілого запису. Конкурентний конфлікт імпорту повертає 409, а не частковий результат. Права власника на імпорт перевіряються на сервері.

`GET /projects/:id?pageId=…&versionId=…` і експорт приймають однакові параметри вибору. Невідповідність сторінки та версії дає 404. Без versionId вибирається остання версія сторінки. Експорт не змішує ключі різних знімків.

Глосарій, мови та учасники спільні для проєкту. Додавання мови створює порожні переклади також для історичних версій; явне видалення мови видаляє її переклади в усіх версіях за попередніми правилами. Це не резервна копія від адміністративного видалення проєкту або мови.

## Міграція та перевірки

Міграція `20260921160000_page_versions` додає сторінку `ui.json` і версію 1 для існуючих ключів. ID, тексти, переклади та попередня історія зберігаються. Неможливо точно відновити старі версії всього файлу лише з історії рядків, тому міграція їх не вигадує.

`node --test tests/pageVersions.test.js` перевіряє незалежність сторінок/версій, збереження історії, перенос статусів, видалені ключі, обмеження редагування архіву, нові мови та точний експорт. Дані тесту ізольовані й прибираються після завершення.

Ця реалізація не містить Git-гілок, merge або автоматичного розв'язання конфліктів між гілками.
