# LocaleFlow

Дипломний проєкт: інформаційна система керування локалізаційними проєктами.

## Технології

- клієнт: React + JavaScript
- запуск клієнта: Vite
- сервер: Node.js + Express
- база даних: PostgreSQL + Prisma

## Структура

```text
client/src/
  api/            запити до сервера
  components/     невеликі повторно використовувані частини інтерфейсу
  pages/          екрани застосунку
  styles/         стилі сторінок і компонентів
  App.jsx         підключає головну сторінку
  main.jsx        запускає React

server/src/
  controllers/    приймають запити й повертають відповіді
  routes/         описують адреси API
  services/       предметна логіка, наприклад імпорт JSON
  utils/          невеликі допоміжні функції
  middleware/     обробляє помилки
  app.js          підключає маршрути та налаштування Express
  server.js       запускає сервер
```

## Запуск

Відкрий два термінали.

### Сервер

```powershell
cd D:\localization-management-system\server
npm run dev
```

### Клієнт

```powershell
cd D:\localization-management-system\client
npm run dev
```

Потім відкрий адресу, яку покаже Vite, зазвичай http://localhost:5173.

## Швидка перевірка

1. Зареєструй перший акаунт — він автоматично стане власником наявного `MyProject`.
2. Відкрий `MyProject` або створи новий проєкт.
3. У редакторі додай українську мову: `uk` — `Українська`.
4. Імпортуй файл `examples/en.json`.
5. У таблиці мають з’явитися 13 ключів локалізації.
6. Як редактор, введи переклад і натисни `Enter`. Підказка під полем показує незбережені зміни.
7. Як рецензент, обери заповнений рядок і натисни «Затвердити переклад» у правій панелі.
   Або вкажи причину й натисни «Повернути на доопрацювання». Редактор бачить зауваження справа та повторно подає текст через Enter.
8. Кнопка «Експорт uk» завантажує готовий `uk.json`.
9. На сторінці проєктів кнопка `✎` змінює назву й опис, а `×` відкриває підтвердження видалення.
10. У редакторі відкрий «Мови проєкту»: цільову мову можна перейменувати або видалити, а мова оригіналу захищена.
11. Натисни «Вийти» та переконайся, що проєкти більше не відкриваються без входу.

## Ролі в проєкті

- `Власник` керує налаштуваннями, мовами, імпортом і командою, але не перекладає;
- `Редактор` вводить та зберігає переклади;
- `Рецензент` перевіряє і затверджує вже збережені переклади.

Власник додає учасника за email зареєстрованого акаунта через пункт «Учасники» в редакторі. Запрошувальні посилання поки не використовуються.

## Основні сторінки

## Сторінки та версії файлів

У редакторі є два окремі списки: «Сторінки» та «Версії» вибраної сторінки. Вибір сторінки відкриває останню версію. Власник створює сторінку через «+ Додати сторінку», указує назву й завантажує JSON. «Імпортувати нову версію» показує різницю перед підтвердженням.

Кожне підтверджене завантаження створює незалежну версію, навіть якщо файл не змінився. Незмінні переклади копіюються зі статусом; змінені мають OUTDATED; нові порожні; видалені ключі залишаються в старій версії. Редактор і рецензент можуть працювати з будь-якою невидаленою версією, зокрема історичною; її зміни не змінюють інші версії. Експорт містить тільки вибрану сторінку й версію; назва файлу в інтерфейсі включає сторінку, номер та мову. Логічно видалені версії недоступні для роботи через API.

Наявні до міграції ключі збережені як `ui.json`, версія 1, без зміни ID та історії. Старі імпорти не перетворюються на вигадані знімки всього файлу. Глосарій і мови залишаються спільними для проєкту. Детальний розбір: `docs/PAGE_VERSIONS_UK.md`.

Приклади: `examples/versions/account-v1.json`, `account-v2.json`, `main-v1.json`. Цільова перевірка з каталогу сервера: `node --test tests/pageVersions.test.js`.

Після отримання цих змін виконай у сервері `npx prisma migrate deploy` та `npx prisma generate`, потім перезапусти сервер. Не використовуй reset для наявної бази.

- `/projects/:id/glossary` — поняття та мовні варіанти, пошук, статуси й бічна форма. Усі учасники пропонують терміни; лише рецензент погоджує та архівує. Автор і рішення показуються в деталях. Новий варіант замінює чинну рекомендацію лише після погодження. Старі записи потребують погодження; авторство для них невідоме. Справа біля перекладів відображаються лише затверджені терміни; там же можна створити пропозицію. Видалення цільової мови видаляє також її записи глосарію.

Перевірка глосарію: редактор або власник пропонує термін → рецензент обирає «На погодженні» та затверджує → редактор бачить рекомендацію біля відповідного рядка. Зміна створює нову пропозицію; попередня версія переходить до архіву після погодження. `npm test` у сервері перевіряє цей цикл із реальною локальною БД, відкочуючи тестові дані.

### Контрольні приклади семантичного вибору

Із каталогу `server` можна виконати `node scripts/checkSemanticExamples.js`. Скрипт використовує реальну модель `Xenova/all-MiniLM-L6-v2`, не змінює БД і записує результат у `docs/semantic-examples.json`. За першого запуску може знадобитися завантаження моделі; подальші запуски використовують локальний кеш. Якщо модель недоступна, неоднозначні приклади можуть залишитися без рекомендації.

Це окрема діагностика, яка не входить до `npm test`. Код завершення 1 означає помилку виконання або невідповідність хоча б одному очікуванню. У поточному наборі три приклади відповідають очікуванням, але коротке `Check the bank.` отримує рекомендацію «банк», хоча очікується невизначеність через брак контексту. Це відоме обмеження, а чотири приклади не є оцінкою загальної точності. Пороги моделі не гарантують правильного вибору; остаточне рішення залишається за користувачем.

- `/projects` — список, створення, редагування та видалення проєктів;
- `/projects/:id` — редактор перекладів вибраного проєкту.
